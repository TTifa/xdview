## 1. Git 的 `link.exe` 抢在 MSVC 前面（构建直接失败）

现象：

```
link: extra operand '...rcgu.o'
LNK1181: 无法打开输入文件 kernel32.lib
```

根因：Git for Windows 自带一个 GNU 的 `link.exe`，`rustc` 按 PATH 找链接器时会误用它，
它当然不认识 MSVC 的参数和 `.lib`。

处理：使用正确的 MSVC/Windows SDK 环境，可运行 `build.bat` 或使用等价 Developer Shell。
当前脚本通过 vswhere 定位工具链并设置 PATH/INCLUDE/LIB，不再调用 vcvars64，演变原因见 §8。

## 2. `-fflags nobuffer` 会吃掉所有帧

最初把所有输入都当成实时流，无脑加低延迟四件套：

```
-fflags nobuffer -flags low_delay -probesize 32768 -analyzeduration 0
```

端到端测试直接失败：

```
[vf#0:0] No filtered frames for output stream, trying to initialize anyway.
[out#0/rawvideo] Output file is empty, nothing was encoded
拉流失败: 未取到任何视频帧
```

逐项隔离后确认元凶是 `-fflags nobuffer`：MP4（moov 在尾部）需要回退式探测，
`nobuffer` 让 demuxer 什么都看不到。**HLS 同理**（要预读分片）。

修正：`is_live_source()` 只对 `rtsp/rtmps/srt/udp/rtp` 打开激进参数，
HLS 与本地文件一律不加，`-rw_timeout` 也只给带 `://` 的网络输入。
单测 `low_latency_flags_only_for_live_sources` 把这条约束钉住。

## 3. 滚动缓存踩的四个坑

| 现象 | 根因 | 处理 |
|---|---|---|
| 父进程被强杀后 ffmpeg 变孤儿，一直在写盘 | `Drop` 不会执行 | Windows **作业对象**（`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`），句柄随父进程关闭自动带走子进程。见 `xd-media/src/sys.rs` |
| 停止时最后一片时长是假的（实测出现 393s） | 曾在窗口退出时未完成显式收尾，ffmpeg 被硬杀 | `App::on_exit` 里显式 `stop()`，给 ffmpeg 发 `q` 优雅收尾 |
| `q` 无效，仍被硬杀 | `input_args` 带了 `-nostdin`，ffmpeg 根本不读 stdin | 缓存进程的参数里删掉它；stdin EOF 不能替代已验证的 Job 异常退出回收 |
| 导出报 `No such file or directory` | concat 清单里的相对路径是相对**清单所在目录**解析的，清单放在导出目录下就指错了 | 清单一律写绝对路径 |

补充两条边界：

- ffmpeg 的 `-strftime` 文件名只有 **1 秒粒度**，切片短于 1 秒会互相覆盖 → `cache_segment_secs` 下限 clamp 到 5。
- 强杀会留下 **0 字节残片**（下一个片段刚开就死了）→ 列表层过滤、清理层删除。

验证命令集中在 [TESTING.md](TESTING.md) §3、§4.3。历史真机记录中录制约 8 秒、收尾后约 8.19 秒；当前版本仍需复验，不能只检查文件存在。

## 4. 排查云台问题时别用画面判断

设备可能开着「智能追踪」（TP-Link 国行实测开启），镜头自己会转：
静置 5 秒两帧的 SSIM 只有 0.38（静止画面本该 >0.9）。
用「发命令前后对比画面」证明云台是否响应是无效的。

优先读 ONVIF `GetStatus` 的归一化角度，但智能追踪也会改变真实角度。
先关闭追踪/巡航并记录静置基线，再核对受控方向、停止及可重复性；详细步骤见 [TESTING.md](TESTING.md) §4.2。

```bat
cargo run -p xd-core --example ptz -- http://ip:2020 user pw verify
```

历史实测输出（TP-Link TL-IPC43AW-COLOR；当时的角度变化不能单独排除追踪干扰）：

```
转动前 pan=+0.0441 tilt=+0.8865
下发 ContinuousMove pan=0.8，持续 900ms …
转动中 pan=-0.0892 tilt=+0.8865
pan 变化量 = 0.1333（历史工具输出的变化量）
```

顺带发现该机**双轴反向**（下发 +pan/+tilt 位置都减小），所以配置里有
`invert_pan` / `invert_tilt` 两个开关。

## 5. 双击 exe 启动读不到 config.toml

**现象**：在项目根 `--check` 一切正常，双击 `target\release\xdview.exe` 却加载到示例配置
（「门口/客厅」），看不到调试好的设备。

**根因**：`config.toml` 按 CWD 解析；双击启动时 CWD 是 exe 所在目录，`load_or_create`
找不到就地写了一份 EXAMPLE 副本（还带明文示例账号，容易误认为是真配置）。

**修法**：`main.rs::resolve_config_path` 按「CWD → exe 同目录 → exe 上两级」找**已存在**的
配置（`target\release` 上两级正好是项目根）；都不存在才落示例。顺手删掉了 `target\release` 下的副本。

**验证**：`cd target\release && xdview.exe --check` 显示 `…\target\release\..\..\config.toml`，
两台真机都在。

## 6. egui SidePanel 宽度反馈回路（面板越长越宽）

**现象**：右侧面板宽度逐帧膨胀 312→499→780…，最后把中央视频区整个盖掉。

**根因**：`Frame::show` 按**内容 min_rect** 分配宽度；`cap_btn` 里 `vertical_centered` 的
min_rect 会撑满整行 → 区块 min_rect 499px → `SidePanel` 把宽度存进 `PanelState` →
下一帧 `default_width` 被存储值覆盖 → `ui.available_width()` 跟涨、内容更宽 → 正反馈。

**修法**：面板 `resizable(false).exact_width(...)` 掐断回路；`ScrollArea` 加
`auto_shrink([false, true])` 限界；自定义按钮改 `allocate_exact_size` + painter 绘制
（确定性宽度，不吃布局 min_rect）。

**验证**：stderr 打印 panel rect 确认宽度恒定；截图三栏布局正常。

## 7. egui `item_spacing` 与 `add_space` 叠加把行撑出面板

**现象**：右栏「采集」第二个按钮、「滚动缓存」开关被面板右缘裁掉。

**根因**：egui 水平布局在控件间**隐式**加 `item_spacing`（默认 8px），代码里又
`add_space(8)` 显式加了一份 → 行总宽 = 2×cw + 16 > 可用宽，`exact_width` 面板下直接裁切。

**修法**：所有等分行先 `ui.spacing_mut().item_spacing.x = 0.0` 再手动 `add_space` 控制间隙；
缓存行用「左列定宽 + 右侧固定宽开关」的确定性分配。

**验证**：截图确认按钮/开关完整等宽；同类行（统计 2×2、预置位、日志）一并处理。

## 8. build.bat 双击「没反应」：UTF-8 中文批处理 + vcvars64 依赖 reg.exe

**现象**：双击 build.bat 窗口一闪而过，target\release\xdview.exe 时间戳不更新；
命令行跑则报一堆 `'误当…MSVC' 不是内部或外部命令`、参数被截断之类的解析乱错。

**根因**（两层叠加）：
1. build.bat 以 **UTF-8 无 BOM + LF** 保存，cmd 按 GBK 解析时中文注释的字节被
   打碎（注释行被当命令执行、`Microsoft.VisualStudio…` 被截成 `crosoft…`），
   脚本在解析阶段就崩了，根本走不到 cargo；
2. 即使解析正常，`vcvars64.bat` 内部用 `reg.exe` 查询 Windows SDK——本机安全
   策略禁用了 reg.exe → vcvars 半途失败（cl 可用但 LIB 缺 SDK），链接报
   `LNK1181: 无法打开 kernel32.lib`；另外 Git 的 PATH 里 GNU `find` 会抢
   `tasklist | find` 的管道。

**修法**：build.bat 改为 **GBK(ANSI) + CRLF** 保存；不再调用 vcvars64，直接用
vswhere 定位 VS 后 `dir /b /o-n` 取最大 MSVC/SDK 版本，手动设置 PATH/INCLUDE/LIB
（并校验 kernel32.lib 存在）；`find` 换成 `findstr`；所有错误分支加 `pause`
（双击时窗口不再闪退）；构建成功打印 exe 时间戳。

**验证**：双击/命令行均能构建，exe 时间戳随源码更新；LNK1181 消失。

## 9. egui SidePanel `resizable(true)` 宽度按内容协商——踩坑 #6 的变体

**现象**：把三栏改成可拖拽（`resizable(true) + width_range`）后，右栏宽度逐帧
+8px 膨胀（322→330→338→…→568 封顶），中部视频区被挤扁；`width_range` 上限
560 也没拦住（实测 568）。

**根因**：resizable 面板宽度会与内容 min_rect **协商**（同 #6 的正反馈机制），
`width_range` 不能根治；`exact_width` 则强制定宽（配合 #7 的可收缩内容一直稳定）。

**修法**：宽度只由**分界手柄拖拽状态**驱动——`exact_width(self.left_w/right_w)`
+ 在中央列左右边缘 `ui.interact` 出 8px 拖拽条（hover 变横向缩放光标并高亮分界线，
clamp 180..440 / 240..560）。彻底绕开内容协商。

**验证**：`--stats` 每 2 秒打 `left_w/right_w/zoom` 布局数值（顺带发现：本机 DPI
≈150% 时 PrintWindow 截的是物理渲染裁剪图，几何测量不可信，数值探针才是准的）。
真机模拟拖拽：左 246→318（+72）、右 314→364（+50）、滚轮 zoom 1.00→1.30、
双击复位 1.00，全部与预期一致。

## 10. UDP connect 取本机 IP 被 VPN/TUN 劫持；增量缓存陈旧让新测试"消失"

**现象**：网段探测扫的是 `198.18.0.0/24`，一台设备都找不到；另一个是新加的
单测在 `cargo test` 里"没注册"（源码里明明有，二进制里搜不到）。

**根因**：
1. `UdpSocket::connect("8.8.8.8:80")` 取本机 IP 的老招，在开了 TUN 代理
   （Clash/mihomo 等，198.18.0.1 是保留段假地址）的机器上拿到的是 TUN 虚拟
   网卡地址，不是局域网真实网卡；
2. target 的 incremental 编译会话残留（伴随"拒绝访问"锁文件告警）让 cargo
   认为测试二进制是新鲜的，新测试没被编进去——`cargo clean -p` 后消失。

**修法**：Windows 下用 `GetIpAddrTable`（iphlpapi，手写 FFI，零依赖）枚举全部
网卡 IPv4，只保留 RFC1918 私网段（198.18/15、169.254/16 全过滤）；测试不进
二进制时先确认 `#[test]`、构建目标与实际重编译情况，再按需 `cargo clean -p <crate>`，不能把所有漏跑都归因于缓存。

**验证**：`--discover` 网段探测从 0 台变成命中两台设备的 ONVIF 服务（分别使用 8080 与 2020 端口）；同 IP 多端口命中（80 网页 + 2020 ONVIF）按
一台算、优先留非 80 端口。这是历史结果，当前测试状态以本次执行为准。

## 11. ONVIF 端点不一定使用约定路径

历史 TL-IPC43AW 接入记录中，默认服务路径返回 404/405，而 GetCapabilities 自报单片 `/onvif/service`。
参见 [摄像机接入指南](CAMERA_SETUP.md) 和 [架构文档](ARCHITECTURE.md) §4.1。

这只能说明该机型的端点形态；Media/PTZ/Device 分离时应分别使用对应 XAddr，不把一个 Media 地址当作通用端点。
验证用本地 socket 桩覆盖分离服务与单片服务，不能只用单片设备通过来推定通用兼容。

## 12. 网络参数按协议排查

2026-10-31 的 Windows 真机记录曾出现代理干扰、GnuTLS 握手 -138 和 RTSP 不识别 rw_timeout；当时 ffmpeg 的完整构建版本未记录，不能推广到所有构建。原始日志与地址只保留本地。

| 现象 | 排查与处理 |
|---|---|
| 直连被送到代理后失败 | 检查子进程继承的代理环境；no_proxy 控制清除代理，不是网络不可达的通用修复 |
| TLS 握手期 IO error -138 | 曾与 rw_timeout 组合有关；按实际 ffmpeg/TLS 后端复现，比较去掉该参数后的结果 |
| RTSP 报 Option rw_timeout not found | 检查实际构建支持的协议参数；本项目 RTSP 使用 timeout，其他输入按协议构造 |
| TLS 证书验证失败 | 检查当前证书链和有效期；历史过期记录不能证明当前仍过期，不默认关闭校验 |

复现时记录 ffmpeg -version 与脱敏后的命令/错误，使用 [TESTING.md](TESTING.md#4-真机验证与排错) 的探针；分享输出前移除凭据、签名路径与设备标识。

## 13. 运行输出不再跟随配置或启动目录

2026-11-01 起，截图、录像、缓存和导出统一使用系统用户数据目录，支持 settings.data_dir 覆盖。旧版将这些文件放在配置文件旁，容易混入源码或受安装目录写权限限制。

规则和迁移方式见 [配置参考](CONFIGURATION.md#运行数据目录)。已有文件不自动搬迁；--check 只展示路径，启动 GUI 时创建根目录，具体输出子目录按需创建。
